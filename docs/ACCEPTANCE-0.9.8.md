# v0.9.8 峰值质量与 MAD 语义修正验收报告

- 日期：2026-10-18
- 版本：`0.9.8`
- 输入日志：W1 +1.5s、W2 −6.0s、W4 −11.25s、W5 −13.75s；W3 相关性不足
- 结论：**旧日志的 6375ms 不是计算错误，但标签有歧义；已改为同时输出标准 MAD 和目标残差 MAD；并增加峰值质量门槛**

## 1. 对 6375ms 的解释

四个有效偏移排序：

```text
[-13750, -11250, -6000, 1500]
```

### 标准 MAD（围绕未加权中位数）

- 中位数 = `-8625ms`
- 到中位数的绝对距离：`5125, 2625, 2625, 10125`
- 标准 MAD = `(2625 + 5125) / 2 = 3875ms`

注意：不是 3625ms；3625 少了 250ms。

### 旧代码的 6375ms

旧代码先算**加权中位数**：

- 权重取相关性分数；
- 加权中位数 = `-6000ms`
- 到加权中位数的绝对距离：`7750, 5250, 0, 7500`
- 残差 MAD = `(5250 + 7500) / 2 = 6375ms`

所以旧日志的 6375ms 是“围绕加权中位数的残差 MAD”，不是标准 MAD。
两者都超过 500ms 阈值，拒绝结果仍然正确。

### 新输出

- `MAD(median)`：标准 MAD；
- `targetResidualMad`：围绕加权中位数的残差 MAD；
- `medianOffset`：未加权中位数；
- `targetOffset`：加权中位数（仅作参考）。

## 2. 新增峰值质量门槛

不做“降低 MAD 阈值”，而是先剔除不可信窗口：

- `margin < 0.03` → `AMBIGUOUS_PEAK`：
  - W1 margin 0.022 ✗
  - W2 margin 0.024 ✗
  - W4 margin 0.021 ✗
- 偏移贴近搜索边界（`maxOffset - 1500ms`）→ `SEARCH_BOUNDARY`：
  - W5 −13750ms 距离 ±15s 边界只有 1250ms ✗
- 相关性低 → `LOW_CORRELATION`：
  - W3 ✗

按这次数据，5 个窗口都不应进入最终聚合。
系统会报告 `NOT_ENOUGH_VALID_WINDOWS`，并保留每个窗口的拒绝原因，而不是拿 4 个低 margin 窗口算出一个 MAD。
